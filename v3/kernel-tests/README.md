# Chameleon v3 kernel driver tests

Purpose of code located in `v3/kernel-tests` directory is to test if
Chameleon v3 kernel driver is working as expected. These tests limits
usage of chameleond to test kernel driver independently from SW stack. This
approach allows to write more "stress test" like scenarios running test's
code directly on Chameleon

## v4l-test-toolbox

`v4l-test-toolbox` is program executed on Chameleon which interact with kernel
driver using ioctls. It controls incoming video stream and does some basic
checks for predefined video pattern.

### Building

Just run `make` on Chameleon. It expects that zlib and gcc are available.

### Example usage

`./v4l-test-toolbox -d /dev/video4 -c 100 -e 3 -f RGB3 -M -R 30000`
Check motion pattern (`-M`) on DP MST (`-d /dev/video4`). Collect 100 frames
(`-c 100`). End after 3 error frames (`-e 3`). Use RGB3 pixel format
(`-f RGB3`). Check 30000 random pixels if color match expected motion pattern
(`-R 30000`).
It is expected that user before running above command prepare following
environment:
* videomux on EC is setup in `dp2 fpga` position.
* HPD is activated
* Video soruce is connected and is displaying "Motion pattern". This pattern
  can be generated on Unigraf. It is composed of 8 vertical bars. Each bar takes
  1/8th of the entire screen. Next expected frame is generated by moving
  the left most column to the right end of the screen. Bars have following
  colors:
    * R: 0xff, G: 0xff, B: 0xff
    * R: 0xff, G: 0xff, B: 0x00
    * R: 0x00, G: 0xff, B: 0xff
    * R: 0x00, G: 0xff, B: 0x00
    * R: 0xff, G: 0x00, B: 0xff
    * R: 0xff, G: 0x00, B: 0x00
    * R: 0x00, G: 0x00, B: 0xff
    * R: 0x00, G: 0x00, B: 0x00

`./v4l-test-toolbox -d /dev/video5 -c 10 -f RGB3 --crc`
Calculate CRC (`--crc`) on DP SST (`-d /dev/video5`). Collect 10 frames
(`-c 10`). Do not end after any error frame (`-e` ommited). Use RGB3 pixel
format (`-f RGB3`). Note that some frames will be missed, since calculating
CRC takes more time than refresh rate.

## Unigraf

To automate kernel test, Unigraf UCD-323 (or probably any other) can be used.
`v3/kernel-tests/unigraf` contains scripts that prepare video stream with
different timings and start `v4l-test-toolbox` over ssh. Scripts are testing
if chamelon is able to successfully read video stream.

Scripts require that python TSI library is available (either it is installed
system wide or source code is in tsi folder next to the scripts) and Unigraf
device is connected to host running the script.

You may need set following arguments to use the script:
* --host IP - IP address of Chameleon
* --ssh_key PATH_TO_KEY - path to ssh private key (default ~/.ssh/testing_rsa)
* --dev DEV - path to video device to test on Chameleon (default /dev/video1)
* --format FORMAT - format of video stream (default RGB3)
* --ucdsn SN - Serial number of UCD device

Kernel tests are written using pytest. Example command starting test for all
timings is (started from `v3/kernel-tests/unigraf`):
`pytest --host 10.77.18.53 --dev /dev/video5 --motion 50 --random 3000`

By default, test for `/dev/video5` and `/dev/vidoe4` will disable `chameleond`
and connect videomux respectively to DP1 and DP2. After test end, `chameleond`
is restarted. To disable this behavior, `--unplug` argument can be provided to
pytest command. In that case, Chameleon must be preconfigured to receive video
from UCD.

### Obtaining TSI

For Windows user, visit https://www.unigraf.fi/downloads/ and download package
with TSI for your's UCD device.

For Linux user:
* Googlers only: visit `Chameleon V3/Unigraf UCD-323` gDrive folder and download
  `Google Example 0.0.5.zip`. Extract archive and run
  `ubuntu/pip_python/install_pip_package_2.sh` to install TSI system wide or run
  test scripts (`kernel_test.py`) from `ubuntu` directory so the script can
  locate tsi in working directory.
* Others: Contact Unigraf Support for Linux TSI package.

### Motion pattern

Motion pattern test is part of `test_kernel.py` test suite. The test configures
motion pattern on Unigraf for various resolutions and checks if there is any
error on Chamelon side. Following arguments can change the test:
* --motion FRAMES - Enables motion pattern test. Number of frames in pattern
  can be adjusted. Always `frames * 2 + 100` frames are tested on Chameleon.
  If frames equals to 0, number of frames to generate equals to width of
  resolution in pixels + 100. Generating large number of frames in high
  resolution may take significant amount of time (up to 10 minutes).
* --random NUM - number of random pixels to check on Chameleon side after
  receiving frame. Setting to high value here may result in putting to much
  stress on Chameleon and missing frames.

### CRC

CRC test is part of `test_kernel.py` test suite. The test sends portion of image
(by default `v3/kernel-tests/unigraf/reference.png`) and checks if CRC
calculated on Chameleon side matches CRC calculated on Unigraf host. Following
arguments can change the test:
* --image PATH - path to the reference image. If image is smaller than requested
  resolution, the image is repeated to fill whole space.
